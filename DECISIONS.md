## Session 1 — Oct 10, 2026

**Decisions**
- **Task domain = bank reconciliation.** It's what Ruth actually did for her family's business, and a reconciliation either balances or it doesn't, so correctness never depends on AI judgment.
- **No database, no login.** Condition 3 says unsuccessful attempts stay private. The strongest way to guarantee that is to never store them. Records live only in links the candidate creates.
- **HMAC-signed links instead of storage.** Without a database the reviewer still needs to trust that the candidate didn't edit the result. The server signs the record and re-grades it itself; any edit breaks the signature.
- **Changed condition from a verified bank of 3 twists, not generated by the LLM.** If Gemini invented the twist, I couldn't guarantee its answer key. The LLM only drafts notes on the explanation.
- **No total score, no pass/fail.** Condition 1 forbids a universal score. The result shows item-by-item evidence and a human signs the decision.
- **Timers record overruns instead of locking the candidate out.** Ruth told me she felt she "wasn't cut out for accounting" after being ignored. A hard lockout would recreate that feeling for nervous candidates. The reviewer sees the overrun and decides.
- **Voice explanation with a text fallback.** Speech recognition isn't available in every browser (Firefox, some iPhones), and nobody should be blocked for their device.
- **Bilingual, Spanish by default.** The users are Mexican; the demo is recorded in English.

**Tomorrow's first move:** run the mechanical test pass on the deployed URL, then the persona test.

## Session 2 — Oct 10, 2026 (mechanical test pass)

**Bug found:** the same start ticket could be submitted again and again (`/api/evaluate` returned 200 twice), and the candidate's result screen showed the expected answers. A candidate could read the key, resubmit on the same ticket and share a "perfect" proof with the original start time. The reviewer couldn't tell.

**Fix:**
- Tickets are single-use: the second submission returns 409 and the UI explains how to correct instead.
- The answer key is shown to the reviewer only. The candidate still sees item by item what differed from expected (condition 3), and corrections go through the visible clarification note, next to the original answer.

**Known limitation (honest):** without a database, single-use is enforced per server instance. On Vercel a determined candidate could still start a new attempt (with a new random twist and a new start time). That's acceptable for the pilot because a new attempt doesn't erase anything: it's a new, separately timed proof. A pilot with real employers would add a tiny attempt log (ticket ids only, no personal data).

**Tomorrow's first move:** persona test with screenshots of every screen.

## Session 3 — Oct 10, 2026 (persona test)

**Persona:** Ruth, 22, built from my User interview (full log in `docs/PERSONA.md`).

**Worst confusion:** the share step showed a huge raw encoded link that "parece virus o de esos mensajes de fraude", with no clear recipient. A quiet quitter would just never send it.

**Decisions:**
- Hide the raw link. Primary action is **WhatsApp with a friendly pre-filled message**; copy is the fallback. That's how Mexican small businesses actually talk.
- Reword everything that sounded like suspicion (tamper note, AI disclosure). Integrity stays the same; only the tone changes.
- Pills say "Coincide con lo esperado" instead of "Correcto", to match the promise that this isn't a grade.
- Deferred: saving progress across app switches (conflicts with private failures on shared phones) and a side-by-side mobile layout.

**Tomorrow's first move:** deploy 2 with these fixes, record the demo on the live URL.

## Session 4 — Oct 10, 2026 (deploy 1 on Vercel)

**Bug found on the live URL:** the full loop worked in production, but every AI draft came back "Simulated AI" even though `GEMINI_API_KEY` was set. Cause: Google now limits `gemini-2.5-flash` to keys that used it before; new keys get HTTP 404, and my code silently fell back.

**Fix:** default to the current stable `gemini-3.8-flash`, then `gemini-3.6-flash` if that one fails; `GEMINI_MODEL` can still override. Each failed model is logged (model + HTTP status, never the key) so the next silent fallback shows up in Vercel Logs.

**Lesson:** a fallback that is labeled honestly is good for users, but it hid a production bug from me. Fallbacks need a log line.
